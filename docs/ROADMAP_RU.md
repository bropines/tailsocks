# План Развития Проекта (Roadmap)

Этот документ описывает планируемые функции, архитектурные улучшения и цели рефакторинга проекта TailSocks.

---

## ✅ Завершённые Этапы
- [x] **Стабильность ядра:** Пассивное управление демоном и декларативная конфигурация.
- [x] **Передача файлов:** Реализация Taildrop с интеграцией в Storage Access Framework.
- [x] **Изоляция профилей:** Мультиаккаунтная система с независимыми каталогами состояния.
- [x] **Сетевые возможности:** Кастомное DNS-обертывание и поддержка Exit Nodes.
- [x] **Tailscale Serve/Funnel:** Нативный UI для хостинга сервисов и публичного доступа.
- [x] **Local API v0:** Управление 100% без CLI через Go-HTTP мост.
- [x] **Интеграция с системой:** Базовая плитка Быстрых настроек (Quick Settings Tile) для переключения подключения.
- [x] **Мониторинг сервисов:** Проверки состояния (health checks) и логи запросов для размещенных сервисов Serve/Funnel.
- [x] **Поиск и фильтрация:** Функция поиска в списке узлов (Peers) и логах.
- [x] **Защита от энергосбережения:** Диалог помощи пользователю по выходу из ограничений батареи.
- [x] **Переключение аккаунтов в плитах:** Расширение плитки Быстрых настроек для переключения между профилями.
- [x] **Прокси панели управления:** Поддержка SOCKS5/HTTP прокси для трафика управления с атомарными патчами и фиксом обхода netns.
- [x] **Зашифрованные бэкапы:** Ручной бэкап состояния приложения, зашифрованный пользовательским паролем (AES-GCM) для защиты ключей узлов.
- [x] **Плитки Быстрых Настроек:** Плитки в шторке Android для управления переключением профилей и состояния подключения.
- [x] **R8-минификация (4.0.0):** `isMinifyEnabled`/`isShrinkResources` включены для релизных сборок. Gson заменён на `kotlinx.serialization`, сервис AppFunctions создаёт сгенерированные KSP реестры напрямую, а Gradle-задача `verifyReleaseNativeMethods` роняет сборку, если R8 удалил JNI-метод.
- [x] **Ужесточение Root-режима (4.0.0):** отдельные цепочки `TAILSOCKS_MARK`/`TAILSOCKS_DNS`, fwmark с маской `0x1000000/0x1000000`, диагностика «Проверить маршрутизацию» и вкладка ROOT в логах.
- [x] **Безопасность автоматизации (4.0.0):** broadcast receiver требует секретный токен; AppFunctions (Gemini, Android 16+) реально выполняются и подчиняются переключателю автоматизации.
- [x] **Доступ из LAN, автопереподключение, восстановление службы в фоне и версионированные бэкапы (4.0.0).**
- [x] **Сосуществование Root-режима с другими VPN (4.0.0):** набор правил разделён на уровни — доступность тайлнета, перехват маршрута по умолчанию, общесистемный редирект DNS, — причём у последних двух на устройстве только один владелец. Появилась частичная уступка: мы берём ровно те uid, которые чужой клиент вывел из своего туннеля, редирект DNS включается только пока MagicDNS отвечает, а интерфейсы с адресом внутри 100.64.0.0/10 больше не захватываются. Проверено на Redmi автора (APatch), в том числе после настоящей перезагрузки.

## 🔮 Будущие Планы
- [ ] **Нативный TUN (4.1):** заменить текущий путь TUN — hev-socks5-tunnel владеет туннелем и заливает весь трафик в SOCKS5-порт демона, то есть два сетевых стека подряд — архитектурой официального клиента: `VpnService` создаёт TUN, а владеет этим fd сам `tailscaled`. Тогда MagicDNS, split-DNS, поисковые домены, маршруты подсетей, Exit Nodes и 100.100.100.100 работают нативно. Не реализовано ничего: архитектура, семь шагов (0–6, последний — необязательная полировка; после каждого приложение остаётся рабочим) и проверки на устройстве, которые надо пройти до кода, лежат в [`NATIVE_TUN_PLAN.md`](NATIVE_TUN_PLAN.md).
- [ ] **Root-режим: закончить проверку на устройствах.** На Redmi автора (Android 16, APatch) проверено: предполётные проверки, определение root, SELinux и доступ к сокету, проба `SO_MARK` демона, весь набор правил сосуществования и автозапуск после настоящей перезагрузки. Осталось:
  - WSA (Magisk, x86_64): автозапуск после перезагрузки через `service.d` и присоединение приложения к демону, которого оно не запускало, — с «Работать в фоне» и включённым, и выключенным.
  - Посмотреть, как чужой туннель перезапускается с новым netId. Раньше потеря его `RETURN` оставляла редирект DNS установленным, а лог при этом продолжал утверждать, что резолвер чужого клиента не тронут; теперь сигнатура учитывает netId, так что правила должны перестроиться — но на устройстве этого никто не наблюдал.
  - Решения, которых ждёт код: давать ли демону, поднятому при загрузке, паритет с запущенным из приложения (адреса SOCKS5/HTTP и режим туннеля — через `/data/adb/tailsocks/control_proxy.env`, превращая их в флаги; сегодня после перезагрузки демон живёт без прокси-слушателей, поэтому Taildrive в «Файлах» и клиенты из локальной сети не работают до ручного перезапуска); нужна ли этому демону аутентификация на SOCKS5 (`TS_SOCKS5_USER` / `TS_SOCKS5_PASS` не экспортируются вообще, так что в Root-режиме слушатель открыт на localhost независимо от полей настроек); должен ли загрузочный скрипт уважать выключенный «Нативный Linux TUN» вместо того, чтобы всегда поднимать `tailscale0`; и приводить ли его права к тем, что ставит приложение (сокет 666, каталог состояния 700, лог 644 вместо 777/777/666).
  - Только если устройство реально это покажет: дождаться CE-хранилища пользователя 0 на телефонах с FBE, не убивать ещё стартующий демон при переустановке загрузочного скрипта, добавить в установленный скрипт версию и показывать «устарел» в настройках.
  - Не зависит от устройства и к проверке на устройствах не относится — отдельное упрочнение, выпавшее из того же разбора: переустанавливать набор правил после того, как перезапуск netd их вычистил (`docs/research/root-exit-node-design.json:281`), и решить, под каким профилем поднимается демон при загрузке. Загрузочный скрипт берёт `files/states/default` или первый найденный `tailscaled.state` (`app/src/main/assets/scripts/tailscaled.sh`), а приложение — `files/states/<activeAccount.id>`; при нескольких профилях после перезагрузки может подняться не та личность, которую ожидает приложение — сегодня `docs/ROOT_RU.md` подаёт этот поиск как удобную функцию и об этом не говорит.
- [ ] **Root-режим: IPv6 в общесистемном редиректе DNS.** И сам редирект, и все исключения вокруг него — это только `iptables -t nat`, `ip6tables -t nat` нет нигде. Поэтому запрос к IPv6-резолверу ни в MagicDNS не заворачивается, ни исключается — ни для исключённого приложения, ни для вышестоящего резолвера. На устройстве с IPv6-резолверами весь этот уровень молча ничего не делает.
- [ ] **Root-режим: утечка мимо exit-ноды по IPv6.** Если в таблице `52` нет маршрута по умолчанию для IPv6, а у телефона есть глобальный v6, то v6-трафик в exit-ноду никто не заворачивает и он уходит напрямую через физическую сеть — это уже утечка мимо exit-ноды, а не уровень, который просто ничего не делает (`docs/research/root-exit-node-design.json:272`). Правило IPv6 ставится best-effort, и его отсутствие пишется в лог (`IPv6 exit-node catch-all not installed`); на устройстве утечку пока не видели, поэтому первый шаг — воспроизвести её на телефоне с глобальным v6 и посмотреть, что на самом деле лежит в таблице `52`.
- [ ] **AI Model Context Protocol (MCP) Сервер:** Встроенный MCP-сервер (JSON-RPC поверх SSE / LocalSocket) поверх `appctr/api.go` LocalAPI, позволяющий ИИ-ассистентам (Claude, Cursor, локальные LLM) опрашивать статус, менять Exit Nodes и управлять профилями.
- [ ] **Нативный Kotlin LocalAPI Мост:** Перевод вызовов LocalAPI с Go (`appctr`) на прямые OkHttp/UnixDomainSocket вызовы в Kotlin, оставляя `libtailscale.so` исключительно для исполнения демона.
- [ ] **Анализатор трафика и диагностика:** Реализация инспектирования активных соединений и запросов MagicDNS прямо в приложении в реальном времени.
- [ ] **Расширенные сетевые функции:** Поддержка пользовательских карт DERP и переопределение региональной маршрутизации.
- [ ] **Уменьшение размера APK:** До включения R8 релиз для arm64 содержал 106.9 МБ без сжатия — 53.1 МБ dex и 50.2 МБ нативного кода (`libtailscale.so` 23.1, `libtailscale_cli.so` 15.4, `libgojni.so` 11.3). R8 и сжатие ресурсов теперь включены (см. выше); оставшийся рычаг — встроенный бинарь CLI `tailscale`, и до любой работы нужно решение автора.
  - Чего он стоит: около 6 МБ в каждом APK под одну ABI — четверть загрузки, — 25 МБ в универсальном и примерно 22 МБ на устройстве, потому что нативные библиотеки распаковываются при установке. Что он даёт: shell-обёртку Root-режима (`su -c tailscale …`) и горстку команд Консоли, у которых уже есть эквиваленты в LocalAPI.
  - **Выбрать из:** (a) оставить как есть — нулевая работа; (b) скачивать по требованию из собственного GitHub-релиза приложения — самый маленький APK, но это загрузчик, проверка хеша, публикация ассетов в CI, привязка версий и вопросы доступности, а скачанный бинарь, скорее всего, сможет запускать только root; (c) флейворы Gradle `lite` / `full` — изменение только сборки, но матрица вариантов удваивается и нужны переименования в CI и поддержка в апдейтере; (d) класть CLI только в универсальный APK — тот же механизм, что и (c), но страница релиза остаётся с пятью файлами (четыре APK по ABI плюс универсальный).
  - Стоит сделать при любом выборе: чтобы отсутствие CLI было видно, а не возвращало пустой результат, и перевести внутренние вызовы CLI на LocalAPI — это заодно чинит `status` / `netcheck` / `ping` в Консоли в Root-режиме, где симлинк на CLI вообще не создаётся.
  - Замечание: `useLegacyPackaging` отключить нельзя — демон запускается через `exec()` из `nativeLibraryDir`, а для этого библиотеки должны быть распакованы на диск.
