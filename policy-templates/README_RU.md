# Шаблоны политики

[English version](README.md)

Готовые куски политики Tailscale (или Headscale), которые предлагает визуальный редактор
политики TailSocks: форма на несколько полей, предпросмотр ровно того, что запишется, и кнопка
«Применить». Каждый шаблон — один JSON-файл в этой папке; ничто в шаблоне не исполняется, и
ничего не скачивается по указке шаблона.

Эта папка — единственная копия. Сборка кладёт её в APK (`assets/policy-templates/`, задача
`copyPolicyTemplates`), так что у приложения эти шаблоны есть всегда; те же файлы публикуются
по адресу `https://bropines.github.io/tailsocks/templates/`, откуда приложение берёт более новые
версии (см. «Откуда приложение их берёт»).

## Как добавить или изменить шаблон

1. Напишите или поправьте `<id>.json` (формат — ниже). Обычный JSON: без комментариев и без
   запятых в конце списков.
2. Меняя опубликованный шаблон, поднимите его `version`.
3. Запустите `python3 policy-templates/update_index.py`: он перепишет `index.json` с `sha256`
   каждого файла (порядок в `index.json` — порядок каталога; новые файлы встают в конец).
4. Запустите `./gradlew :app:testDebugUnitTest --tests '*Template*'`. `BundledTemplatesTest`
   падает, пока файл не разбирается, нарушает правило ниже или расходится с `index.json`; ещё он
   применяет каждый шаблон к нескольким политикам на обоих бэкендах.

## Откуда приложение их берёт

1. **Встроенные**: копия в APK. Есть всегда.
2. **Удалённые**: `https://bropines.github.io/tailsocks/templates/index.json` и файлы из него —
   только по HTTPS, через подключение консоли администратора (её настройку прокси), не чаще
   раза в шесть часов при открытии каталога или по ручному обновлению. Индекс — не больше 64 КБ,
   каждый файл — 64 КБ, весь набор — 1 МБ; файл, чей `sha256` не совпал с индексом, отвергается,
   как и тот, что не разбирается или нарушает правило.
3. **Кеш**: последний удалённый набор, прошедший проверку, в файлах приложения.

Удалённый (из кеша) шаблон заменяет встроенный с тем же `id`, только если его `version` выше,
а приложение не старше его `minApp`; новый `id` добавляется после встроенных.

## Файл шаблона

```json
{
  "schema": 1,
  "id": "tailsocks-remote",
  "version": 1,
  "minApp": "5.1.0",
  "category": "remote-management",
  "title": { "en": "TailSocks remote management", "ru": "Удалённое управление TailSocks" },
  "description": { "en": "…", "ru": "…" },
  "headscale": { "supported": true, "note": { "en": "…" } },
  "docs": [ { "title": { "en": "Access rules" }, "url": "https://tailscale.com/kb/1337/policy-syntax" } ],
  "suggest": [ { "page": "access", "slot": "after", "when": "!check:open" } ],
  "params": [ … ],
  "checks": [ … ],
  "fragments": { … }
}
```

| Поле | |
|---|---|
| `schema` | Версия формата: 1. Файл более новой схемы пропускается. |
| `id` | Постоянный, kebab-case (`own-devices`), не длиннее 64 символов. |
| `version` | Целое от 1; удалённый файл заменяет встроенный, только если она выше. |
| `minApp` | Необязательно: самое старое приложение, которому шаблон годится, — имя версии (`"5.1.0"`) или код версии (`5010000`). |
| `category` | Kebab-case: `access`, `ssh`, `exit-nodes`, `subnets`, `taildrive`, `remote-management`, `relays`, `dns`, `funnel`, `k8s`, `guests`, `baseline`, … Фильтр каталога. |
| `title`, `description` | Текст по языкам; `en` обязателен, `ru` ожидается. Пустая строка в описании начинает часть, которая остаётся свёрнутой. |
| `headscale` | `supported`: `true`, `false` или `"partial"`, и необязательная `note`. `false` прячет шаблон на Headscale; при `"partial"` показывается пояснение. |
| `docs` | Ссылки со страницы шаблона: только `https` и только tailscale.com, headscale.net, github.com или bropines.github.io. |
| `suggest` | Необязательно: где страница редактора показывает шаблон отдельной карточкой, помимо каталога. `page`: `access`, `attributes`, `peer-relays`; `slot`: `empty` (среди шаблонов пустой страницы), `before` (над списком), `after` (под ним); `when` — условие, считается со значениями формы по умолчанию. |

### Параметры

```json
{ "id": "managers", "kind": "selector", "slot": "remote-from", "allow": ["user", "group", "tag"],
  "label": { "en": "Who manages" }, "help": { "en": "…" }, "required": true, "multi": true,
  "default": ["autogroup:member"] }
```

`id` — строчными (`[a-z][a-z0-9_-]*`); `label` обязателен, `help` — нет; `required` и `multi` —
false, если не сказано иное. `default` — строка, список строк (`multi`) или булево значение.

| `kind` | Поле формы | Значение |
|---|---|---|
| `selector` | Собственный выбор редактора для `slot`; с `allow` — только перечисленные виды (`any`, `autogroup`, `group`, `tag`, `user`, `user-domain`, `host`, `ip`, `cidr`, `ipset`, `service`, `posture`). | То, что пишет выбор: `group:admins`, `tag:web`, `alice@example.com` (у Headscale — `alice@`), `autogroup:member` … |
| `user`, `group`, `tag` | Тот же выбор, только этот вид. | |
| `port` | Чипы портов и список вручную. | `22`, `8000-8100`, `*` — по одному в элементе. |
| `host` | Текстовое поле. | IP-адрес. |
| `cidr` | Текстовое поле. | Адрес с длиной префикса: `192.168.1.0/24`. |
| `text` | Текстовое поле, проверка по `format`: `any`, `name`, `tag-name`, `login`, `duration`. | Не длиннее 200 символов. |
| `bool` | Переключатель. | `true` / `false`; не бывает `multi`. |
| `choice` | Чипы из `options` (`[{"value": "check", "label": {…}}]`). | Один `value` (несколько при `multi`). |

`slot` — это слоты выбора редактора: `acl-src`, `acl-dst`, `grant-src`, `grant-dst`,
`grant-via`, `ssh-src`, `ssh-dst`, `ssh-user`, `node-target`, `tag-owner`, `approver`,
`test-src`, `test-dst`, `ssh-test-src`, `ssh-test-dst`, `group-member`, `posture`, `relay-src`,
`relay-dst`, `remote-from`, `remote-to`. Слот решает, какие автогруппы выбор предложит на каждом
бэкенде; `selector` без слота не бывает, у `user`/`group`/`tag` по умолчанию `acl-src`.

### Фрагменты

Что «Применить» сливает в политику, по разделам. `fragments` — один блок (объект из разделов)
или список блоков, у каждого может быть свой `when`:

```json
"fragments": [
  { "access": [ … ], "tests": [ … ] },
  { "when": "param:approve", "autoApprovers": { "exitNode": ["{{who}}"] } }
]
```

**Списки** — `access`, `acls`, `grants`, `ssh`, `nodeAttrs`, `tests`, `sshTests`: каждый
элемент добавляется в конец своего раздела (раздела нет — он создаётся). Элемент, который в
политике уже есть (тот же JSON, как бы он ни был свёрстан), второй раз не пишется. У элемента
могут быть два ключа, которые в политику не попадают никогда:

- `when` — условие; элемент пишется, только пока оно выполняется;
- `comment` — текст по языкам, пишется комментарием над элементом (заполнители можно).

**`access`** — правило доступа в нейтральной форме; пишется в том синтаксисе, которым файл уже
пользуется (которого в нём больше правил; в пустом файле — гранты на Tailscale, ACL на Headscale):

```json
{ "src": ["{{managers}}"], "dst": ["{{managed}}"], "ports": ["28115"], "proto": "tcp" }
```

`src` и `dst` обязательны; `ports` по умолчанию `["*"]`; `proto`, `via` и `srcPosture` — по
желанию. Как ACL: `{"action": "accept", "src": …, "dst": ["<dst>:<порты через ,>"], "proto": …}`.
Как грант: `{"src": …, "dst": …, "ip": ["<proto>:<порт>", …]}`; элемент с `via` — всегда грант.
Элемент, у которого `src` или `dst` получился пустым, не пишется. Правило на `autogroup:self` от
тега отвергается до «Применить» (у тега нет своих устройств).

**Объекты** — `groups`, `tagOwners`, `ipsets`, `postures`: список под каждым ключом сливается со
списком того же имени — недостающие значения дописываются после имеющихся, а нет списка — он
создаётся. `hosts`: имя и адрес; имя, которое в файле уже указывает на другой адрес, — конфликт,
и «Применить» не даётся. `autoApprovers`: `routes` (префикс → кто одобряет), `exitNode` (кто
одобряет) и `services` (сервис → кто одобряет), сливаются так же.

Любой другой раздел отвергается: шаблон не трогает `derpMap`, уже имеющиеся правила и вообще
ничего, чего сам не добавил.

### Заполнители

Строка может назвать параметр как `{{id}}` или `{{id|join}}` — и в ключах, и в значениях;
подставляется только значение из формы, и ничего больше. Во что превращается строка, зависит
от того, где она стоит:

| Где | Только `"{{p}}"` | С текстом вокруг: `"{{host}}:{{port}}"` |
|---|---|---|
| Элемент списка | Все элементы `p`, вставленные на её место; пусто — ничего. `bool` — одно булево значение. | По строке на каждое сочетание элементов заполнителей, первый меняется медленнее всех: `["a:22", "a:80", "b:22", "b:80"]`; ничего, если хоть один пуст. |
| Значение поля | Параметр `multi` — список его элементов. Одиночный — его значение. `bool` — булево значение. Писать нечего — поле не пишется. | Одна строка; каждый заполнитель в ней — одиночный, `bool` или с `|join`. |
| Ключ | Одна строка, как значение с текстом вокруг. | Одна строка, так же. |

`{{p|join}}` — всегда одна строка: элементы через `,` (`"80,443"`). Параметр `multi` без
`|join` там, где должна стоять одна строка, — ошибка, её находят при чтении файла. `{{` или `}}`
вне заполнителя — тоже ошибка.

### Условия

`when` (у блока, элемента или подсказки) — имена, связанные `!`, `&&`, `||` и скобками:

- `param:<id>` — параметр задан (переключатель включён, список не пуст); `param:<id>=<value>` —
  один из его элементов равен этому значению;
- `check:<id>` — проверка выполняется;
- `headscale`, `tailscale` — бэкенд;
- `style:acls`, `style:grants` — синтаксис, которым пишутся новые правила доступа.

### Проверки

Что в политике уже есть — решается до того, как что-то запишется. Пока проверка выполняется,
страница показывает её `note`; условия называют её `check:<id>`. В списках можно заполнители.

| `kind` | Поля | Выполняется, когда |
|---|---|---|
| `access-open` | `src`, `dst`, `ports`, `proto` | Правила файла уже пускают каждый источник к каждому получателю на всех `ports` (без условий о состоянии устройства и без `via`). Страница показывает эти правила. |
| `grant-app` | `cap` | Какой-то грант несёт эту возможность приложения. |
| `node-attr` | `attrs` | Каждый атрибут включает какое-нибудь правило атрибутов устройств. |
| `relay-devices` | `relays`, `clients` | Список устройств показывает устройство, которое не примет участия (телефон не бывает реле, клиент старше 1.86, чужое устройство), или клиенты — все подряд: страница их перечисляет. |

### Возможности движка

То, что является логикой, а не данными, остаётся в приложении, а шаблон просит его по имени:

- `"generate": "pair-test"` в `tests`, с `src`, `dst`, `port` и необязательным `proto`: один
  тест, который сторожит новый путь, — от первого источника, который тест может назвать
  (пользователь, группа, тег), к первому такому же получателю на `port`; при известном списке
  устройств — пара, у обеих сторон которой устройства есть; теста нет, если он в файле уже есть
  или назвать пару нельзя.
- Проверка `access-open` (поиск дублей удалённого управления) и `relay-devices` (что список
  устройств говорит о реле и их клиентах).

## Ограничения

Не больше 16 параметров, 16 проверок и 50 элементов на шаблон; тексты — до 4000 символов;
значения — до 200. В индексе — не больше 100 шаблонов.
