Настройки → **Режим туннеля**, один из трёх. Переключать можно когда угодно.

| Режим | Что нужно | Что идёт в tailnet |
|---|---|---|
| **Прокси** | ничего | приложения, которые вы направите на локальный прокси |
| **VPN (TUN)** | разрешение VPN | адреса tailnet, а с выходным узлом — всё |
| **Root** | root (Magisk, KernelSU, APatch) | всё устройство, через интерфейс ядра `tailscale0` |

## Прокси

Разрешение VPN не нужно, поэтому режим уживается с любым другим VPN или блокировщиком рекламы. На устройстве работают:

| Что | По умолчанию | Где настроить |
|---|---|---|
| SOCKS5 | `127.0.0.1:48115` | Локальные прокси → **Адрес SOCKS5** |
| HTTP | `127.0.0.1:8080`, выключен, пока не включить **Включить HTTP-прокси** | Локальные прокси → **Адрес HTTP-прокси** |
| DNS для имён tailnet | `127.0.0.1:1053` | DNS → **Адрес DNS-прокси** |

- Направьте на них браузер, приложение или прокси-клиент (Exclave, NekoBox…). **Копировать ссылку SagerNet** даст ссылку `socks5://`.
- **Имя пользователя SOCKS5** и **Пароль SOCKS5** работают только вместе: одно поле без другого игнорируется.
- **Открыть прокси в локальную сеть** открывает все три для вашего Wi-Fi. Сначала задайте пароль SOCKS5: без него ваш tailnet доступен любому в сети.
- Без выходного узла интернет-трафик через прокси уходит через обычную сеть телефона, с ним — через выходной узел.

### Доступно из tailnet

В режиме прокси, с движком hev-socks5-tunnel и в Root-режиме без его интерфейса демон работает в userspace. Соединение с другого устройства tailnet на tailnet-адрес этого устройства, на порт, который сам демон не обслуживает, уходит на тот же порт `127.0.0.1` — так Tailscale работает в этом режиме. Значит, устройства, которых политика tailnet пускает к этому, могли пользоваться прокси TailSocks, его веб-интерфейсом и пробросами TailCat так, будто те работают у них.

С 5.1.0 собственные порты TailSocks из tailnet закрыты. Настройки → Локальные прокси → **Доступно из tailnet** открывает прокси по одному: **SOCKS5 из tailnet**, **HTTP-прокси из tailnet**, **DNS-прокси из tailnet**, **Прокси Taildrive из tailnet**. У веб-интерфейса и пробросов TailCat переключателя нет, они остаются закрытыми.

- Пользовались прокси телефона с другого устройства tailnet? Включите его здесь. Сначала задайте пароль SOCKS5; HTTP-прокси пароля не спрашивает никогда.
- Службы других приложений — adb по сети на 5555, SSH-сервер, Syncthing — доступны, как на любом узле Tailscale в userspace. **Строго: закрыть из tailnet и всё остальное** закрывает и их, кроме портов из поля **Оставить открытыми порты** под ним: `5555, 8022, udp:1234`.
- Порт удалённого управления, 28115, подчиняется только переключателю **Разрешить удалённое управление**. Taildrop, папкам Taildrive и Serve эти переключатели не нужны.
- Демон подхватывает изменение примерно за секунду, без перезапуска.
- С настоящим интерфейсом — нативный движок TUN, `tailscale0` Root-режима — переключатели ничего не меняют: до порта на `127.0.0.1` tailnet там не достаёт никогда. А с интерфейсом Root-режима прокси, открытые в локальную сеть, доступны и из tailnet.

Настройки → Дополнительно → **Что открыто на этом устройстве** показывает всё, что доступно из интернета, tailnet или локальной сети, и у каждого пункта — переключатель, который это закрывает. Тот же список есть в отчёте диагностики.

### Вместе с AdGuard

AdGuard может отдавать имена tailnet TailSocks, а остальное фильтровать как обычно.

1. В AdGuard → Управление приложениями → TailSocks выключите «Направлять трафик через AdGuard», иначе получится петля.
2. AdGuard → Настройки → Общие → Расширенные → Низкоуровневые настройки:
   - **Резервные upstream-серверы** (`dns.fallback_upstream`): добавьте `127.0.0.1:1053`.
   - **Резервные домены** (`dns.fallback_domains`): добавьте `*.ts.net` и ваши домены split DNS.
3. AdGuard → Настройки → Прокси: добавьте SOCKS5-прокси `127.0.0.1:48115` (ваш **Адрес SOCKS5**). До адреса `100.x` можно достучаться только через него — одного имени мало.
4. Проверьте: откройте имя из tailnet, например `my-laptop.example.ts.net`.

## VPN (TUN)

Пропускает устройство через VPN-интерфейс Android. Слот VPN Android отдаёт одному приложению, поэтому включение сначала спросит (**Занять слот VPN?**).

- **Без выходного узла** через VPN идут только tailnet и принятые маршруты подсетей — или весь трафик, в [прозрачном режиме](#прозрачный-режим).
- **С выходным узлом** — весь трафик.

Настройки → Режим туннеля → **Настройки режима TUN**:

- **Движок TUN** — **Нативный** (по умолчанию): туннелем управляет сам `tailscaled`, MagicDNS, split DNS и выходные узлы работают напрямую через него. **hev-socks5-tunnel** — движок для совместимости: каждый пакет идёт через локальный SOCKS5. Берите его, если нативный ведёт себя странно.
- **Пересобирать туннель на ходу** — только у нативного движка, по умолчанию включено. См. [пересборку туннеля на ходу](#туннель-пересобирается-на-ходу).
- **Весь IPv6 через туннель** — по умолчанию выключено. Включайте, только если выходной узел умеет IPv6, иначе сайты с IPv6 будут висеть.
- **Прозрачный режим** — по умолчанию **При блокировке Android**. См. [прозрачный режим](#прозрачный-режим).
- **Исключенные подсети IP** — при включённом выходном узле остаются в обычной сети (Android 13+).
- **Исключенные приложения** — остаются вне туннеля.

### Туннель пересобирается на ходу

Android фиксирует маршруты VPN в момент, когда VPN поднимается. Поэтому включение и выключение выходного узла и изменения в принятых подсетях требуют нового VPN. Переход с одного выходного узла на другой — не требует.

На нативном движке TailSocks поднимает новый VPN рядом со старым, и работающий демон переходит на него за несколько миллисекунд, без перезапуска. Если это не удалось, демон перезапускается на новом VPN — несколько секунд без tailnet. Если выключить **Пересобирать туннель на ходу**, он перезапускается всегда.

### Прозрачный режим

Без выходного узла VPN несёт только tailnet. А «**Блокировать соединения без VPN**» в Android (настройки VPN в Android, рядом с **Постоянной VPN**) режет всё, что не идёт в VPN, — без выходного узла это весь интернет.

В прозрачном режиме VPN забирает весь трафик. То, что для tailnet, идёт в tailnet; остальное уходит напрямую — на нативном движке его устанавливает демон, на hev-socks5-tunnel — SOCKS5-прокси. Принятые маршруты подсетей по-прежнему идут к устройствам, которые их предлагают. Если выбран выходной узел, весь трафик несёт он, а прозрачный режим не вмешивается.

| Вариант | Когда включён |
|---|---|
| **При блокировке Android** (по умолчанию) | только пока включено «**Блокировать соединения без VPN**». TailSocks сам следит за этим переключателем, в пределах 15 секунд. |
| **Всегда** | всегда, когда выходной узел не выбран. |
| **Выключен** | никогда. Без выходного узла блокировка тогда оставляет телефон без интернета. |

Чем платите:

- В принципе медленнее прямого пути. Замер на телефоне по Wi-Fi: около 4,6 МБ/с и с ним, и без него.
- Ping и прочий ICMP в интернет не проходят.
- IPv6 в интернет идёт через него, только если включено **Весь IPv6 через туннель**. Без этого при блокировке приложения переходят на IPv4.

<details>
<summary>Как он следит за блокировкой</summary>

Включено ли «Блокировать соединения без VPN», Android сообщает только работающему VPN-сервису и никому не говорит, когда это меняется. Поэтому TailSocks спрашивает при каждом обновлении статуса, раз в 15 секунд, и пересобирает туннель, когда ответ меняется, — на нативном движке на ходу.

Пересобранный VPN забирает маршрут по умолчанию, `0.0.0.0/0`, а `::/0` — только с **Весь IPv6 через туннель**. На нативном движке демон принимает TCP и UDP телефона к адресам вне tailnet, которые не ведёт ни один пир, и устанавливает эти соединения заново сам; демон остаётся вне VPN, так что блокировка его пропускает. На hev-socks5-tunnel каждое соединение и так идёт в SOCKS5-прокси, а он устанавливает то, что не для tailnet, как для любого приложения.

</details>

### Другое VPN-приложение заняло слот

Когда слот VPN Android занимает другое VPN-приложение — AdGuard, Exclave… — TailSocks продолжает работать как прокси: tailnet остаётся доступен через его [локальные прокси](#прокси). Главная карточка пишет: *Слот VPN занял другой VPN. TailSocks продолжает работать как прокси; переподключитесь, чтобы вернуть слот.*

TailSocks возвращает слот, только когда вы его переподключите. Изменение настроек слот не забирает.

## Root (экспериментально)

На рутованном устройстве (Magisk, KernelSU, APatch) демон работает через `su` на настоящем интерфейсе ядра `tailscale0`, с policy routing. Слот VPN в Android остаётся свободным.

Выберите **Root** в Настройки → Режим туннеля (на телевизоре: Настройки → Дополнительно → Root-режим). Переключатели — в карточке **Root-режим и системная служба (ЭКСПЕРИМЕНТАЛЬНО)**: интерфейс ядра, загрузочный скрипт, команда `tailscale` для root-консоли.

- С выходным узлом через него идёт всё устройство, кроме **Исключенных приложений**; **Системный DNS через MagicDNS** (Настройки → DNS) отправляет DNS всех приложений в MagicDNS.
- Рядом с другим VPN-приложением он уступает: адреса tailnet, имена MagicDNS и локальные прокси работают, а приложения, которые тот VPN оставил вне туннеля, идут через выходной узел.
- После перезагрузки загрузочный скрипт возвращает tailnet; выходной узел и системный DNS появляются, когда работает приложение.

Всё о нём — настройка, соседство с другим VPN, загрузочный скрипт, поиск неполадок — на странице [Root-режим](/tailsocks/ru/root-mode/).
